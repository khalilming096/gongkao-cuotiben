# 公考错题本

按「模块 → 子模块 → 子类 → 知识点 → 错误记录」记录公考错题，勾选一次即累计一次错误，数据本地持久保存。

| 文件 / 目录 | 说明 |
| --- | --- |
| `公考错题本-v2.1.0.apk` | **安装包**，传到手机点击安装（Android 8.0+），可直接覆盖旧版安装，数据保留 |
| `index.html` | **Web 版**，单文件，手机浏览器直接打开，数据存 localStorage |
| `android/` | **原生工程**，Kotlin + Jetpack Compose + Room，可继续二次开发 |

---

## 一、层级结构

```
模块（固定 5 个）
 └─ 子模块（仅言语理解 2 个、判断推理 4 个）
     └─ 子类（共 27 个）
         └─ 知识点（手动新增：名称 + 错误原因）
             └─ 错误记录（勾选一次生成一条，累计次数 +1）
```

- **政治理论、常识、资料分析**：考点线性、题量集中，不设子模块，知识点直接挂在模块下。
- **言语理解、判断推理**：题型差异直接决定解法，加一层子模块 + 子类，避免清单混在一起。

---

## 二、子模块与子类（含细分维度与依据）

### 言语理解 —— 2 个子模块 / 10 个子类

| 子模块 | 细分维度 | 子类 |
| --- | --- | --- |
| 逻辑填空 | 按「先看语境、再辨词语」的解题顺序 | 语境对应、实词辨析、成语辨析、关联词与虚词、多空综合 |
| 片段阅读 | 按「设问方式」——问什么决定找什么、找多细 | 中心理解、细节判断、标题填入、语句表达、篇章阅读 |

逻辑填空子类逐个说明：

- **语境对应**：解释、反对、并列、递进四类逻辑关系的呼应点没找准——这是逻辑填空的第一顺位，先定语境再定词。
- **实词辨析**：词义侧重、搭配范围、语体色彩三项辨析不清。
- **成语辨析**：望文生义、褒贬误用、对象误用、语义轻重——成语的错法高度固定，单列一类便于集中复盘。
- **关联词与虚词**：转折、因果、条件、递进的搭配错位，考点独立且可枚举。
- **多空综合**：多空题不是新考点，而是**策略**问题（未按先易后难、逐空排除处理），故单列。

### 判断推理 —— 4 个子模块 / 17 个子类

| 子模块 | 细分维度 | 子类 |
| --- | --- | --- |
| 图形推理 | 按「规律类型」，同时也是考场上的观察顺序 | 位置规律、样式规律、数量规律、属性规律、立体与分组 |
| 定义判断 | 按「定义数量 + 设问方向」 | 单定义判断、多定义辨析、反向设问 |
| 类比推理 | 按「关系层级」——先语义、再逻辑、最后语法 | 语义关系、逻辑关系、语法关系、二级辨析 |
| 逻辑推理 | 按「题型与论证结构」 | 翻译推理、真假推理、加强削弱、日常结论、解释评价 |

图形推理子类的排序即解题顺序：元素组成相同看**位置**，相似看**样式**，凌乱看**数量**，规整看**属性**，都不像再考虑**立体与分组**。

## 三、为什么这样分（三条规则）

1. **子模块按题型切，与试卷题号顺序一致**。考场上想到的是「这是道图形推理」，不是「这是道判断推理」，所以第二层必须落在题型上。
2. **子类按解法差异切**。同一子模块下的子类必须对应**不同的解题动作**——如果两个子类解法一样，就合并。这条规则用来防止「分类很细但复盘时没有区别」的无效分类。
3. **能不设层就不设层**。政治理论、常识、资料分析不设子模块：这三个模块考点线性、单题耗时长，多加一层只会增加点击成本，不会提升复盘价值。

## 四、功能与需求的对应关系

| 需求 | 实现位置 |
| --- | --- |
| 主界面固定五个模块入口 | `HomeScreen`；模块用枚举 `StudyModule` 固定 |
| 进入模块展示知识点清单 | 有子模块 → 先看子模块列表（`GroupScreen`）；无子模块 → 直接看清单（`ModuleScreen`） |
| 子模块内按子类细分 | `SubModuleScreen`：顶部筛选条 + 按子类分组，组标题带该子类的判定依据 |
| 手动新增知识点名称 + 错误原因 | 底部操作条 → 弹窗（先选子类，再填名称与原因） |
| 每条知识点可勾选 | 卡片左侧圆圈，点一下即勾选，4.5 秒内可撤销 |
| 勾选一次新增记录、累计 +1 | `recordOneError()`：插入记录 + `errorCount+1`，同一事务 |
| 单条记录可编辑 / 删除 | 详情页每条记录「⋯」→ 备注 / 删除这一次，次数同步回退 |
| 清单展示名称、错因、累计次数 | 卡片：名称 + 「错因」标签 + 右侧「N 次」 |
| 查看对应错误记录 | 详情页倒序列出「第 N 次错误 + 时间 + 备注」，顶部显示层级面包屑 |
| 持久保存、可重复累计 | Android 用 Room；Web 用 localStorage |

## 五、交互设计（v2.1）

### 1. 新增知识点的位置：底部固定操作条

入口位置比较过三种方案：

| 方案 | 优点 | 问题 |
| --- | --- | --- |
| 顶部栏加「＋」图标 | 进页面就能看到 | 图标只有 24dp，和返回、说明挤在一起，不够显眼 |
| 清单第一项做成「＋ 新增」卡 | 不遮挡内容、和卡片同构 | 滚到列表中段就看不见，要滚回顶部 |
| **底部固定操作条（采用）** | 全宽 54dp、常驻可见、拇指自然落点 | 占约 74dp 高度，靠列表底部留白补偿 |

选底部条的原因：新增是这一页最高频的两个动作之一（另一个是勾选），高频动作应该**常驻且命中面积大**，而不是挂在角落靠用户去找。同时把它和「勾选圆圈」在空间上分开——勾选在卡片左侧，新增在屏幕底部，两者不会误认。

列表底部预留 96dp 内边距，最后一张卡片不会被按钮压住。

### 2. 勾选防误触：撤销窗口

勾选仍然是一次点击即记录（不弹确认框，否则连续记错题会很烦），但记录后底部提示条会保留 **4.5 秒撤销窗口**：

```
✓ 已记录「语境对应」第 4 次    撤销
```

点「撤销」即删除刚插入的那条记录并把累计次数减 1，界面立刻回滚。撤销只针对**最近一次**，避免一次误点被撤掉多笔。

新增知识点同样可撤销：保存后提示条给「撤销」，点了就把刚建的知识点连同可能已产生的记录一起删掉。

### 3. 单条记录管理：详情页「⋯」

详情页每条错误记录右侧有「⋯」，点开是该条记录的操作面板（标题写明是哪个知识点的第几次）：

- **添加/修改备注**：补写这道题错在哪（如「2023 联考 A 卷第 12 题，漏看『不』字」），备注显示在记录时间下方；
- **删除这一次**：二次确认后删除该条，累计次数减 1，其余记录的「第几次」自动重排。

删除单条不可撤销，所以给了确认框；勾选误触可撤销，所以不打断操作——两处的防护强度按可逆性区分。

### 4. 数据一致性

`recordOneError` / `undoLatestRecord` / `removeRecord` 三个操作都在 Room 事务里完成「写/删记录」与「次数 ±1」，保证 `errorCount` 永远等于该知识点的记录条数，不会出现次数和列表对不上。

## 八、数据结构

```kotlin
KnowledgePoint(id, moduleKey, groupKey, subKey, name, reason, errorCount, createdAt)
ErrorRecord(id, pointId, timestamp, note)
```

- `moduleKey`：`zzll` / `cs` / `yy` / `pd` / `zl`
- `groupKey`：`ltk`、`pdyy`、`txxx`、`dypd`、`lbtl`、`ljtl`；无子模块时为空串
- `subKey`：子类 key，如 `cyby`（成语辨析）；无子模块时为空串
- `note`：单条错误记录的备注，可为空
- `errorCount` 与 `ErrorRecord` 条数严格一致（同一事务内变更）
- 删除知识点级联删除其记录（`ForeignKey.CASCADE`）

分类目录集中在 `model/Catalog.kt`，改分类只动这一个文件，三个界面自动跟随。
