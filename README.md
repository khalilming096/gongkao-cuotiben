# 公考错题本

按「模块 → 题型 → 子类 → 知识点 → 错误记录」记公考错题的次数与时间，勾选一次即累计一次错误。

**定位**：不存题干、不存解析，只记「哪个知识点在反复错、错了几次、什么时候错」。题目本身交给「错题复盘」的题库（藏题，18,011 题），错题本只负责统计与定位。

两套产物同源：网页版单文件（`index.html`）与安卓原生工程（`android/`），共用一份自动生成的分类表。

## 二、分类体系：由题库生成，不手写

扫描题库里 18,011 道题的 `source` 路径（如 `判断推理/…/图形推理/数量规律-面/10204456 xxx.md`）统计得出：

| 模块 | 题量 | 题型 | 子类 |
| --- | --- | --- | --- |
| 言语理解 | 6,762 | 3 | 17 |
| 判断推理 | 7,728 | 5 | 28 |
| 资料分析 | 3,521 | 6 | 33 |
| **合计** | **18,011** | **14** | **78** |

各题型的子类（括号内为题量，只列前几项）：

- **片段阅读**（2963）：中心理解 1600、细节判断 918、标题填入 253、词句理解 170、其他
- **逻辑填空**（2690）：实词填空 990、混搭填空 879、成语填空 744、语境分析 51、词的辨析 26
- **语句表达**（1109）：语句填空 386、语句排序 355、下文推断 186、病句辨析 110、语句衔接 32…
- **逻辑判断**（2482）：加强削弱 1019、分析推理 405、翻译推理 314、前提假设 210…（共 11 类）
- **图形推理**（1873）：数量规律 553、立体图形 381、样式规律 334、位置规律 324、属性规律 279
- **类比推理**（1640）：对应关系 756、逻辑关系 516、语义关系 259、语法关系 84、范围关系 25
- **定义判断**（1602）：单定义 1262、多定义 340
- **科学推理**（131）：物理 81、化学 27、物理推理 14、其他
- **增长**（1198）：一般增长率比较 275、一般增长率计算 186、增长量计算 181…（共 12 类）
- **比重**（787）：现期比重 471、基期比重 104、统计图选择 83、两期比重差 73…
- **综合分析**（612）：选是型 434、选非型 178
- **简单计算**（395）：简单加减计算 193、排序比较 178、直接找数 23
- **平均数**（284）：现期平均数 189、平均数增长率 36、基期平均数 30…
- **倍数**（245）：现期倍数 165、基期倍数 38、现期倍数比较 29、现期追赶 13

**两条生成规则**：

1. 题量 < 10 的子类合并为「其他」，避免筛选条被 1 题的小类塞满（原始有 300 多个细分）；
2. 每个子类保留题库里最常见的细分名（如「中心理解」下面是关联词-对策 396、主题词 362、关联词-转折 285），新增知识点时可以点选，不用自己想名字。

政治理论、常识、数量关系三个模块题库里没有对应题型，直接挂模块级知识点。

## 三、错因按题型区分

错因不是一套通用标签，而是「题型专属 + 通用兜底」两层：

- **专属错因**（蓝色）：该题型最典型的失分动作，由 `tools/gen_catalog.py` 里的 `TOPIC_ERRORS` 定义，随分类表一起输出；
- **通用错因**（灰色）：审题不清、时间不够、蒙错、知识点遗忘。

| 题型 | 专属错因 |
| --- | --- |
| 片段阅读 | 没抓中心句、以偏概全、偷换概念、答非所问、无中生有 |
| 逻辑填空 | 呼应点找错、词义侧重混、搭配对象错、褒贬误用、望文生义 |
| 语句表达 | 首尾句判错、话题不统一、关联词错位、语序判错 |
| 图形推理 | 规律没看出、数量数错、元素组成判错、空间想不出 |
| 定义判断 | 要素漏抓、主体范围错、设问看反 |
| 类比推理 | 一级关系判错、二级辨析漏、词性不一致 |
| 逻辑判断 | 论点论据找错、削弱加强弄反、翻译规则记错、力度比较错 |
| 科学推理 | 公式记错、单位换算错、概念混淆 |
| 增长 | 公式混淆、时间定位错、截位位数错、增长量与率混 |
| 比重 | 部分整体找错、基期现期搞混、两期方向判错 |
| 平均数 | 分子分母找错、增长率与量混 |
| 倍数 | 倍数与多几倍混、基期现期找错 |
| 简单计算 | 加减错位、排序看漏、单位不统一 |
| 综合分析 | 选项顺序乱、漏看「不正确」、中途放弃 |

政治理论、常识、数量关系没有题库题型，走模块级错因（时政记混／法律条文混／公式记错等）+ 通用兜底。

两处输入框文案也随层级变化：错因框提示该题型的典型错法，名称框提示该子类在题库里最常见的细分名。

## 四、功能

| 功能 | 位置 |
| --- | --- |
| 主界面六个固定模块，显示我的知识点数与累计错误；题库规模降级到页脚淡字 | 主页 |

| 导出 / 导入备份 | 右上角「ⓘ」 |

## 五、数据结构（v3）

```js
point  = {id, mod, g, s, name, reason, count, created}
record = {id, pid, ts, n: 备注, q: 题库题号}
```

- `mod`：`zzll`（政治理论）/ `cs`（常识）/ `yy`（言语理解）/ `sl`（数量关系）/ `pd`（判断推理）/ `zl`（资料分析）
- `g`：题型 key，如 `pdyy`（片段阅读）、`zz`（增长）；空串表示未归类
- `s`：子类名，如 `中心理解`、`一般增长率计算`
- `count` 与该知识点的记录条数保持一致（勾选、撤销、删除都在同一步里同步）

旧数据（v1/v2）首次打开会自动迁移：英文子类 key 按 `Catalog.legacyMapping` / `LEGACY_SUB_MAP` 换成题库分类，映射不到的归入「未归类」，可在题型列表底部进入重新归类。

安卓端同一套字段落进 Room（数据库 version 4）：`knowledge_points` 对应 point，`error_records` 对应 record，另有 `note` / `qid` 两列。

## 六、备份与恢复

- **导出**：说明弹窗 → 导出备份，下载 `cuotiben-backup-YYYYMMDD.json`，结构 `{app, version, points, records}`
- **导入**：说明弹窗 → 导入备份，按「模块 + 题型 + 子类 + 名称」识别同一个知识点
  - 重复的知识点：次数取较大值，错因取新值，创建时间取较早
  - 记录按时间戳去重，不会重复累加
  - 导入只增不减，不会覆盖现存数据

网页版数据在 `localStorage` 的 `gk_cuoti_v3`，安卓在 App 私有目录的 `cuotiben.db`。**两端不互通**，搬家只能走导出/导入。

## 七、从粉笔采集数据同步错题

```bash
python tools/sync_fenbi.py                       # 用默认采集目录
python tools/sync_fenbi.py <采集目录>            # 指定批次
```

产出在 `data/<采集批次>/`：`backup.json`（导入用）、`同步报告.md`（映射明细）、`raw/`（原始数据留档）。

映射规则：

| 环节 | 规则 |
| --- | --- |
| 模块 | 言语理解与表达→`yy`，判断推理→`pd`，资料分析→`zl`，常识判断→`cs`，数量关系→`sl`，政治理论→`zzll` |
| 标签→子类 | 先精确匹配，再按前缀最长匹配（`对应关系-前后呼应`→逻辑填空/语境分析） |
| 归属 vs 名称 | 归属用题型层（实词/混搭/成语填空），名称用技巧层（对应关系/词的辨析），形成「混搭填空 / 对应关系-前后呼应」 |
| 材料类型 | 资料分析的「文字资料/统计图/综合资料」是载体不是考点，直接忽略 |
| 对不上 | 归「未归类」，App 里可手动重新归类 |
| 次数 | 一道错题＝一条记录，`count` 恒等于记录数，不会虚高 |
| 题号 | `question_alias` 写进记录，用于回题库翻原题 |

同一批次重复导入不会翻倍（合并式导入，记录按时间戳去重）。

安卓端不走导入按钮：把 `backup.json` 复制成 `android/app/src/main/assets/seed-backup.json`，
`data/SeedImporter.kt` 会在**首页首次启动时**把它写进 Room（IO 线程、单事务、只导一次，用 SharedPreferences 的 `fenbi_seed_v1` 标记）。数据库里已有数据则跳过，不会覆盖。

## 八、题库更新后重新生成分类

```bash
python tools/gen_catalog.py      # 读题库 source 路径 → catalog.json
python tools/inject_catalog.py   # 把 catalog.json 注入 index.html
cp catalog.json android/app/src/main/assets/catalog.json
```

三处必须一致，否则网页版和 App 的分类会对不上。

- `tools/gen_catalog.py` 的 `BANK_DIR` 指向题库目录（默认 `~/Documents/错题复盘/app/dist/data`），题库搬家要改；
- `MIN_SUB = 10` 控制长尾合并阈值；
- `TOPIC_KEYS` 保证题型 key 稳定（旧数据迁移依赖它，改 key 会让历史记录掉进「未归类」）。

## 九、仓库里不包含什么

个人数据与安装包只留在本地，`.gitignore` 已排除：

| 路径 | 是什么 | 怎么重新生成 |
| --- | --- | --- |
| `*.apk` | 安卓安装包 | `android/rebuild.bat` 或 gradle `assembleDebug` |
| `data/` | 粉笔采集记录、错题备份、同步报告 | `python tools/sync_fenbi.py` |
| `android/app/src/main/assets/seed-backup.json` | 首启内置的错题数据 | 复制 `data/<批次>/backup.json` |
| `*.db` / `cuotiben-backup-*.json` | 本地数据库与导出备份 | App 内导出 |
| `userscripts/` / `.testdata/` | 本地调试用的第三方脚本与预览副本 | — |
| `.workbuddy/` | 项目开发记录 | — |

所以 clone 下来直接编译，App 是空的（没有内置错题）；想要数据就得自己生成一份放进去。

## 十、已知限制

- 网页版与安卓端数据不互通，只能导出/导入；
- 安卓端还没有备份导入导出 UI（网页版有）；
- 没有复习调度和统计页，目前只记录「错了几次、什么时候错」，不做到期提醒。
